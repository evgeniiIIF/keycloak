# Keycloak BFF — Production-Ready Hardening Plan

## Current State Summary

BFF is a NestJS 10 app with express-session backed by Redis, Keycloak OIDC (PKCE), and a proxy to a protected service. Key gaps: hardcoded session secret fallback, no helmet, no rate limiting, no input validation, no tests, no health checks, no structured logging, and missing token-refresh-on-401 logic.

---

## Phase 1 — Critical Security (must ship first)

### 1.1 SESSION_SECRET without default
**File:** `bff/src/configs/configuration.ts`, `bff/src/main.ts`

- Remove `|| 'your-secret-key'` from `process.env.SESSION_SECRET` in `main.ts`.
- In `configuration.ts`, throw a startup error if `SESSION_SECRET` is missing or < 32 chars.
- Add `SESSION_SECRET` to `.env.example` and `docker-compose.yml` environment blocks.

### 1.2 Helmet
**File:** `bff/src/main.ts`, `bff/package.json`

- `npm i helmet @types/helmet`
- In `main.ts`: `app.use(helmet())` before session middleware.
- This adds `Strict-Transport-Security`, `X-Content-Type-Options`, `X-Frame-Options`, `Content-Security-Policy`, etc.

### 1.3 Trust proxy + dynamic secure cookie
**File:** `bff/src/main.ts`

- `app.set('trust proxy', 1)` (NestJS wraps Express).
- Cookie `secure`: `config.nodeEnv === 'production'`.
- Add `NODE_ENV` to `configuration.ts` with default `'development'`.

### 1.4 Session Fixation prevention
**File:** `bff/src/controllers/auth.controller.ts`

- In `callback()` handler, after `handleCallback()` succeeds, call `req.session.regenerate((err) => { ... })` and re-populate session data inside the callback.
- Alternative: use `req.sessionID = generateId()` + `req.session.regenerate()` pattern from `express-session` docs.

### 1.5 Backchannel logout jti replay protection
**File:** `bff/src/services/auth.service.ts` (new method), `bff/src/controllers/auth.controller.ts`

- After JWT verification in `backchannelLogout`, extract `payload.jti`.
- Check Redis: `if (await redis.exists(\`replay:${jti}\`)) → 401`.
- Set: `await redis.set(\`replay:${jti}\`, '1', 'EX', <token_exp + buffer>)`.
- Use the singleton JWKS (see 2.5) instead of creating per-request.

### 1.6 CSRF → double-submit cookie
**File:** `bff/src/guards/csrf.guard.ts`, `bff/src/main.ts`

**Current problem:** CSRF token lives in session → checking it requires a valid session → logout with expired access token fails.

**Double-submit cookie pattern:**
1. On first request (or login), generate random CSRF token, set it as a **httpOnly=false, sameSite=strict cookie** (`XSRF-TOKEN`) AND store the same value in session.
2. `CsrfGuard` reads cookie value and compares to `X-X-CSRF-Token` header — no session lookup needed.
3. Attacker cannot read the cookie (sameSite=strict, httpOnly=false so JS reads it but cross-origin cannot).
4. Logout works without valid session: CSRF check succeeds via cookie alone.

Changes:
- `main.ts`: set `XSRF-TOKEN` cookie on session init (or in a middleware).
- `CsrfGuard`: read `req.cookies['XSRF-TOKEN']` (needs `cookie-parser`), compare to `req.headers['x-csrf-token']`.
- Remove `session.csrfToken` usage from `AuthService` and `AuthController` `/api/me` response.

### 1.7 Rate limiting
**File:** `bff/src/main.ts`, new `bff/src/throttler.config.ts`, `bff/package.json`

- `npm i @nestjs/throttler`
- Register `ThrottlerModule.forRoot([{ ttl: 60000, limit: 10 }])` in `AppModule`.
- Apply `@UseGuards(ThrottlerGuard)` to: `callback`, `logout`, `refresh`, `backchannelLogout`.
- Separate stricter limits for `/api/auth/refresh` (e.g. 5/min).

### 1.8 Input validation
**File:** `bff/src/main.ts`, new `bff/src/dto/*.dto.ts`, `bff/package.json`

- `npm i class-validator class-transformer`
- Global pipe: `app.useGlobalPipes(new ValidationPipe({ whitelist: true, forbidNonWhitelisted: true }))`.
- DTOs: `CallbackQueryDto { code: string; state: string }`, `LogoutBodyDto`, etc.
- Apply `@Query(CallbackQueryDto)` on `callback()`.

### 1.9 CORS from env
**File:** `bff/src/configs/configuration.ts`, `bff/src/main.ts`

- Add `CORS_ORIGINS` env var (comma-separated).
- Parse into array in config, default to `[config.frontendUrl]`.
- `enableCors({ origin: config.corsOrigins, ... })`.

## Phase 2 — Session & Token Management

### 2.1 Rolling sessions
**File:** `bff/src/main.ts`

- Add `rolling: true` to session options. Cookie renews on each request.

### 2.2 Auto-refresh token on 401 from downstream
**File:** `bff/src/http/axios.ts`, `bff/src/http/httpClient.ts`, `bff/src/controllers/protected_service.controller.ts`

**Current state:** Refresh logic is duplicated in each proxy method of `protected_service.controller.ts`. This violates DRY.

**Proper approach — axios interceptor:**
1. Create a factory function `createAxiosInstance(authService, session)` that returns an axios instance with a response interceptor.
2. The interceptor catches 401, calls `authService.refreshAccessToken(session)`, retries the original request with new token.
3. `httpClient.ts` becomes a class that accepts the session-aware axios instance.
4. Controller simply calls `httpClient.get(...)` — no retry logic in controller.

Changes:
- `axios.ts`: Add `createSessionAxios(session, authService)` factory that creates an axios instance with 401-retry interceptor.
- `httpClient.ts`: `HttpClient` constructor accepts an `AxiosInstance` parameter.
- `protected_service.controller.ts`: Inject `AuthService`, create session-aware httpClient per request, simplify to just call `httpClient.get/post`.

### 2.3 Token expiry check before proxying
**File:** `bff/src/guards/session.guard.ts`

- Decode `session.accessToken` JWT, check `exp`.
- If expired (or expiring within 30s), attempt refresh.
- If refresh fails, throw `UnauthorizedException`.
- Use `jose.jwtDecode` (no verification needed — just reading claims; the token was verified at issuance).

### 2.4 Logout with invalid/expired session
**File:** `bff/src/controllers/auth.controller.ts`

- Remove `SessionGuard` from `logout` — only `CsrfGuard` remains.
- With double-submit CSRF (1.6), CSRF check works without a valid session.
- If `session.accessToken` is expired/missing, skip `unregisterSession` (no sub available) but still destroy session and redirect to Keycloak logout.
- If `session.userInfo?.sub` is available, call `unregisterSession` before destroying.

### 2.5 Singleton JWKS
**File:** new `bff/src/services/jwks.service.ts`

- Create a NestJS `@Injectable()` singleton that creates `createRemoteJWKSet` once.
- Provide `getJWKS()` method that returns the cached instance.
- Inject into `AuthController` for `backchannelLogout`.
- Consider periodic refresh (every 1h) via `setInterval`.

## Phase 6 — Additional Security Hardening

### 6.1 RP-Initiated Logout with refresh_token revocation via /revoke
**File:** `bff/src/services/auth.service.ts`, `bff/src/configs/configuration.ts`

- Use Keycloak's token revocation endpoint (`RFC 7009`):
  `POST {issuer}/protocol/openid-connect/revoke`
  Body: `client_id=...&client_secret=...&token=<refresh_token>&token_type_hint=refresh_token`
- This is separate from the `/logout` endpoint — revoke is for server-side token invalidation.
- Call this in `logout()` before destroying the session, and in `backchannelLogout` after destroying sessions.
- The `/logout` endpoint (used for RP-initiated browser redirect) handles the browser session — revocation handles the token itself.

### 6.2 Background session cleanup
**File:** `bff/src/services/redis.service.ts`

- Optional: periodic task (`@nestjs/schedule`) to scan `user_sessions:*` keys and remove orphaned references.

### 6.3 CORS multi-origin
Already covered in 1.8.

## Verification Plan

1. **Config validation**: Remove `SESSION_SECRET` from env → app should refuse to start.
2. **Helmet**: `curl -v http://localhost:3000/login` → response headers include `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, etc.
3. **Rate limiting**: Send 11 rapid requests to `/callback` → 429 response.
4. **Session fixation**: After login callback, verify session ID changes (check cookie value).
5. **Token refresh**: Start proxy request, expire access token → verify 401 triggers refresh + retry.
6. **Health checks**: `curl http://localhost:3000/health` → 200; stop Redis → readiness returns 503.
7. **Graceful shutdown**: `docker stop bff_service` → logs show clean disconnect, no errors.
8. **Tests**: `npm test` passes with >80% coverage on critical paths.
9. **Lint**: `npm run lint` exits cleanly.
