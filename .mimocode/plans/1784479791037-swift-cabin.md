# Fix: Multiple Sessions + Empty Session Bug

## Root Cause Analysis

### Problem 1: "Empty session used instead of token session"

The login flow creates **TWO sessions**:

1. `GET /login` — `buildAuthorizationUrl()` stores `oauth` (state + codeVerifier) in the session → express-session saves it to Redis → browser gets `Set-Cookie: connect.sid=ID_A`
2. `GET /callback` — `session.regenerate()` **destroys** ID_A from Redis, creates ID_B with new ID → tokens saved to ID_B → `Set-Cookie: connect.sid=ID_B`

After this, the browser should have cookie for ID_B (with tokens). But there's a critical race:

- `regenerate()` destroys ID_A from Redis and sets `Set-Cookie` for ID_B
- But at the END of the request, express-session middleware's `end` handler also runs
- With `rolling: true`, it refreshes the cookie. If the middleware's internal state still references the old session somehow, it could overwrite the cookie back to ID_A

**Result**: Browser cookie → ID_A (destroyed in Redis) → express-session creates a NEW empty session with ID_A on the next request → user gets "session not authenticated".

### Problem 2: Multiple sessions in Redis

The 3 sessions you see are:
1. **Session from `GET /login`** — with `oauth` data, then partially destroyed by `regenerate()`
2. **Empty session** — created when browser sends old cookie after `regenerate()` destroyed it
3. **Session with tokens** — the correct one from `GET /callback`, but the browser doesn't have its cookie

### Problem 3: No state validation (CSRF vulnerability)

`OAuthCallbackInterceptor` checks that `state` exists but never validates it against `session.oauth.state`. The state parameter is generated and stored but never verified — this is a CSRF vulnerability.

## Solution: Eliminate Pre-Auth Session

**Don't store `oauth` state in the session at all.** Use a signed cookie instead. This eliminates the need for a session during the login flow, so only ONE session is ever created — the one with tokens.

### How it works:

1. `GET /login` → Generate state + codeVerifier → Store in Redis with key `oauth:<state>` (TTL 10 min) → Set `state` as a signed, httpOnly, short-lived cookie → Redirect to Keycloak
2. `GET /callback` → Validate `state` cookie matches query `state` → Retrieve codeVerifier from Redis by `state` → Exchange code → Create NEW session with tokens → Delete `oauth:<state>` from Redis → Redirect to client
3. No `session.regenerate()` needed, no intermediate session created

### Why this is better:
- **Exactly one session per login** — no intermediate session at `GET /login`
- **Session fixation protection** — no session exists before auth, so there's nothing to fixate
- **CSRF protection** — state is validated against Redis, not just checked for presence
- **Cleaner** — no fragile `session.regenerate()` + `oauth` save/restore dance

## Files to Modify

### 1. `bff/src/auth/services/auth.service.ts`
- Remove `session` parameter from `buildAuthorizationUrl()` — it no longer needs the session
- Instead: generate state + codeVerifier, store in Redis, set signed cookie on response
- `performLogin()`: remove `session.regenerate()` — just create tokens on the existing session
- Add `validateCallback()` method: read state cookie, validate against Redis, retrieve codeVerifier
- Delete `oauth` from session type (no longer needed)

### 2. `bff/src/auth/controllers/auth.controller.ts`
- `login()`: pass `res` to `buildAuthorizationUrl()` so it can set the oauth cookie
- `callback()`: read `state` from cookie, pass to `handleOAuthCallback()`
- Remove `OAuthCallbackInterceptor` (state validation moves to service layer)

### 3. `bff/src/redis/services/redis.service.ts`
- Add `setOAuthState(state, codeVerifier, ttl)` — stores `oauth:<state>` → codeVerifier
- Add `getOAuthState(state)` — retrieves codeVerifier
- Add `deleteOAuthState(state)` — cleans up after use
- Add constant: `OAUTH_STATE_PREFIX = 'oauth'`

### 4. `bff/src/types/session.d.ts`
- Remove `oauth` field from `SessionData` — no longer needed

### 5. `bff/src/session/services/session.service.ts`
- Remove `setOAuth()` and `clearOAuth()` methods — no longer needed
- Remove `regenerate()` method — no longer needed

### 6. `bff/src/auth/interceptors/oauth-callback.interceptor.ts`
- Simplify or remove — state validation moves to service layer with Redis lookup

### 7. `bff/src/config/config.ts`
- Add `oauthStateTtl` (default 600 seconds / 10 minutes)
