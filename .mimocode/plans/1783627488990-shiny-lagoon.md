# Audit: SOLID / DRY / KISS + TypeScript Typing Quality

## Executive Summary

The project is a small (~700 LOC) NestJS BFF for Keycloak auth. Architecture is generally clean and well-structured, but there are **significant TypeScript typing issues** rooted in two critical config choices: `strictNullChecks: false` and `noImplicitAny: false` in tsconfig.json, plus `no-explicit-any: off` in ESLint. This opens the door to `as any` casts and weak type safety throughout. SOLID/DRY/KISS violations are moderate — mostly from repeated patterns that could be extracted.

---

## 1. TypeScript Typing (Critical)

### 1.1 Root Cause: tsconfig.json disables strict checks

```
"strictNullChecks": false,    // line 17
"noImplicitAny": false,       // line 18
"strictPropertyInitialization": false  // line 19
```

These three settings effectively disable TypeScript's core safety net. Combined with `@typescript-eslint/no-explicit-any: off` in eslint.config.js:23, the project has **zero enforcement** against `any` usage.

**Recommendation:** Enable `strict: true` (enables all three + more). Fix resulting errors.

| auth.controller.ts | 25 | `req.session as any` |

| auth.controller.ts | 82 | `req.session as any` |

### 1.4 `any` usage in test code (5 instances)

security.middleware.spec.ts lines 16, 24, 27, 28, 30 and request-context.spec.ts lines 5, 6. Less critical but indicates types aren't well-defined enough for testing.

### 1.5 Missing/Incomplete Types

- **session.d.ts**: Missing `id?: string` — causes all `session as any` casts
- **No `Config` interface**: config.ts uses `as const` inference. Works but no explicit documentation type.
- **`TokenSet` interface** in keycloak-client.ts:8-12 is local-only, not shared with auth.service.ts
- **`SessionWithAuth`** in security.middleware.ts:32-36 duplicates session.d.ts
- **`KeycloakJwtPayload`** in security.middleware.ts:38-42 — local, same JWT payload decoded in auth.service.ts:44-49
- **`UpstreamError`** in proxy.controller.ts:7-10 — ad-hoc local type
- **HttpClient generic params never used**: `get<T>`, `post<T>` etc. have generics but proxy.controller.ts never specifies T — returns `unknown` in practice

## 2. SOLID Principles

### 2.1 Single Responsibility Principle

**auth.controller.ts (158 lines)** — Too many responsibilities:
- OAuth login flow (login, callback)
- User info endpoint (me)
- Token refresh (refresh)
- User logout (logout)
- **Keycloak backchannel logout** (backchannel-logout, lines 115-157) — this is a completely separate protocol concern

**security.middleware.ts (128 lines)** — The `use()` method handles 4 distinct jobs:
1. Route matching (path + method)
2. Session validation + token expiry checking
3. CSRF double-submit validation
4. Role-based authorization

These should be separate concerns (or at least separate private methods with clear boundaries).

**main.ts (95 lines)** — Bootstrap handles: Redis session setup, CSRF token middleware, CORS config, security middleware registration, server startup. Could use NestJS middleware modules.

### 2.2 Open/Closed Principle

**proxy.controller.ts:54-64** — `proxyMutate` uses switch/case on method strings:
```typescript
switch (method) {
  case 'POST': result = await this.http.post(url, req.body); break;
  case 'PUT': result = await this.http.put(url, req.body); break;
  case 'DELETE': result = await this.http.delete(url); break;
  case 'PATCH': result = await this.http.patch(url, req.body); break;
}
```
Adding a new method requires modifying this switch. A method map would be more extensible.

### 2.3 Interface Segregation

**SessionWithAuth** (security.middleware.ts:32-36) uses `[key: string]: unknown` index signature — too permissive. Should only declare the properties actually accessed.

### 2.4 Dependency Inversion

- **HttpClient** directly instantiates `axios` — no abstraction. Makes testing harder.
- **RedisService** exposes raw `client` property — all consumers use `this.redis.client.sAdd()`, `this.redis.client.expire()`, etc. Should have typed wrapper methods (e.g., `addUserSession()`, `removeUserSession()`, `getUserSessions()`).
- **Logger** is a static module imported directly — not injected via DI.

## 3. DRY Violations

### 3.1 Repeated `req.session as any` pattern (5 times in auth.controller.ts)

Lines 25, 31, 75, 82, 92 — identical cast. Fix: extend the Request type or create a helper.

### 3.2 Repeated error message extraction (8+ times)

`err instanceof Error ? err.message : 'unknown'` found in:
- auth.controller.ts: lines 67, 84, 102, 153
- keycloak-client.ts: lines 62, 79
- http-client.ts: line 94
- jwks.service.ts: line 17

**Fix:** Extract `function errorMessage(err: unknown): string`.

### 3.3 Repeated Redis key patterns in auth.service.ts

`user_sessions:${userId}` appears 4 times (lines 76, 99, 100, 108, 114).
`${config.session.prefix}${sid}` appears 2 times (lines 83, 112).

**Fix:** Constants or RedisService wrapper methods.

### 3.4 Duplicate JWT payload types

`KeycloakJwtPayload` in security.middleware.ts and the inline type in auth.service.ts:44-49 are the same shape.

## 4. KISS Violations

### 4.1 Hand-rolled glob matcher (security.middleware.ts:7-18)

`matchPath()` implements `**` wildcard matching from scratch. For a BFF with ~10 routes, this is over-engineered. A simple `startsWith`/exact match would suffice, or use NestJS's built-in guard system with `@SetMetadata`.

### 4.2 Inline CSRF middleware in main.ts (lines 59-75)

A 17-line anonymous middleware closure that generates tokens, sets cookies, and saves sessions. Should be a dedicated middleware class (like SecurityMiddleware already is).

### 4.3 HttpClient boilerplate (http-client.ts)

Five nearly-identical methods (get/post/put/delete/patch) that all do `this.instance.METHOD(url, ...); return res.data`. Could be a single `request(method, url, data?)` method.

## 5. Recommended Fixes (Priority Order)

### Phase 1: TypeScript Strictness (Critical)
1. Enable `"strict": true` in tsconfig.json (replaces the 3 disabled flags)
2. Fix `session.d.ts` — add `id?: string` to Session augmentation
3. Create shared types: `KeycloakJwtPayload`, `TokenSet` — put in `src/types/`
4. Remove all `as any` in production code
5. Enable `@typescript-eslint/no-explicit-any: 'warn'` in eslint.config.js
6. Fix all resulting type errors

### Phase 2: DRY
7. Extract `errorMessage(err: unknown): string` utility
8. Create Request helper or extend Express Request type to eliminate `session as any`
9. Extract Redis key constants or create typed wrapper methods in RedisService
10. Consolidate JWT payload types into shared types

### Phase 3: SOLID / KISS
11. Split auth.controller.ts — extract backchannel-logout to separate controller
12. Extract CSRF middleware to its own class
13. Replace proxy switch/case with a method map
14. Add RedisService wrapper methods instead of exposing raw client
15. Simplify matchPath() or replace with NestJS guards
