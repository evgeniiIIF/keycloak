# Fix: Custom Keycloak Login Theme 500 Error

## Root Cause

`login.ftl` line 2 references `social.displayInfo`, which doesn't exist in Keycloak 26.6. The `social` hash has no `displayInfo` property — FreeMarker throws an exception when the macro is invoked, producing the 500 error.

Additionally, the custom `login.ftl` creates its own full card layout (`login-container > login-card`) **inside** the base `template.ftl`'s own card wrapper (`kcFormCardClass`). This causes visual nesting/duplication but is not the crash cause.

## Plan

### Step 1 — Fix `social.displayInfo` (the crash)

**File:** `themes/custom-login/login/login.ftl`

Replace line 2:
```ftl
<@layout.registrationLayout displayInfo=social.displayInfo; section>
```
With (matching base theme's approach):
```ftl
<@layout.registrationLayout displayInfo=realm.password && realm.registrationAllowed; section>
```

### Step 2 — Override `template.ftl` for full layout control

Since the custom theme has its own card/centered layout, we need to provide a `template.ftl` that renders the HTML shell **without** the base theme's card/form wrappers — otherwise the custom `login-card` div nests inside the base `kcFormCardClass` div.

**New file:** `themes/custom-login/login/template.ftl`

Minimal template that:
- Renders `<!DOCTYPE html>`, `<head>` with styles from `theme.properties`, and `<body>`
- Calls `<#nested "form">` directly (no card wrapper)
- Includes the locale selector if internationalization is enabled
- Includes message/alert display

This way the custom `login.ftl` has full control over its own layout.

### Step 3 — Update `theme.properties`

Add the necessary CSS class properties and meta that the template.ftl expects (or set them to empty strings if not used). Keep `parent=base` and `import=common/keycloak`.
