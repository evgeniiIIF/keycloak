# Fix: Detailed JWT rejection logging in protected-service

## Problem
Protected-service returns 401 but doesn't log WHY the JWT failed (expired? wrong issuer? wrong audience? signature mismatch?). This makes it impossible to diagnose the `invalid_grant` root cause.

## Change
**File:** `protected-service/index.js`

Replace the catch block (lines 94-113) with detailed logging that shows:
- Expected vs actual issuer
- Expected vs actual audience
- Token expiry time vs current time
- The raw error message from `jose`

## Verification
1. `docker compose up`
2. Login, navigate to `/service`
3. After 401, check protected-service logs — should see which JWT claim failed
