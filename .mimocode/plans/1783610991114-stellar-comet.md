# Куки в проекте Keycloak BFF — где устанавливаются и читаются

## Куки проекта

| Cookie | httpOnly | sameSite | Назначение |
|--------|----------|----------|------------|
| `connect.sid` | `true` | `lax` | Сессия (express-session) |
| `XSRF-TOKEN` | `false` | `strict` | CSRF double-submit token |

---

## Где куки УСТАНАВЛИВАЮТСЯ (Set-Cookie уходит в браузер)

### 1. `connect.sid` — экспресс-сессия (автоматически)
- **Файл:** `bff/src/main.ts:45-50`
- express-session автоматически ставит куку `connect.sid` при первом ответе сервера.
- Опции: `httpOnly: true`, `secure` (в проде), `sameSite: 'lax'`, `maxAge` из конфига.

### 2. `XSRF-TOKEN` — CSRF-мидлварь
- **Файл:** `bff/src/main.ts:56-63`
- На каждый запрос проверяется: если куки `XSRF-TOKEN` нет — генерируется рандомный 32-байтный hex-токен и ставится через `_res.cookie('XSRF-TOKEN', token, { httpOnly: false, secure, sameSite: 'strict', path: '/' })`.
- **Важно:** `httpOnly: false` — это сделано намеренно, чтобы фронтенд мог прочитать токен (double-submit cookie pattern).

### 3. Очистка при logout
- **Файл:** `bff/src/controllers/auth.controller.ts:116-117`
- `res.clearCookie('connect.sid', { path: '/' })`
- `res.clearCookie('XSRF-TOKEN', { path: '/' })`

---

## Где куки ЧИТАЮТСЯ из браузера

### Серверная часть (cookie-parser → req.cookies)

1. **Парсинг всех кук:** `bff/src/main.ts:27` — `app.use(cookieParser())` превращает заголовок `Cookie` в `req.cookies`.

2. **Проверка XSRF-TOKEN перед установкой:** `bff/src/main.ts:56` — `req.cookies['XSRF-TOKEN']` — проверяет, есть ли уже кука (чтобы не перезаписывать).

3. **CSRF-валидация:** `bff/src/guards/csrf.guard.ts:8` — `request.cookies?.['XSRF-TOKEN']` — сравнивает значение куки с заголовком `X-CSRF-Token` из запроса.

4. **express-session** автоматически читает `connect.sid` из кук для идентификации сессии.

### Клиентская часть (браузер)

**Клиент НЕ читает куки через `document.cookie`!** Вместо этого:

- **`client/src/api/api.ts:5`** — `withCredentials: true` на инстансе axios заставляет браузер автоматически отправлять все куки (`connect.sid`, `XSRF-TOKEN`) с каждым запросом к BFF.

- **CSRF-токен хранится в localStorage, НЕ в куке (на клиенте):**
  - Запись: `client/src/context/AuthContext.tsx:30` — при получении `/api/me` фронтенд сохраняет `csrf_token` в `localStorage`.
  - Чтение: `client/src/api/api.ts:14-16` — при POST/PUT/DELETE/PATCH фронтенд берёт токен из `localStorage` и отправляет как заголовок `X-CSRF-Token`.
  - Удаление: `client/src/context/AuthContext.tsx:36` — при ошибке авторизации.

## Схема CSRF-защиты (double-submit cookie)

```
Браузер                     BFF                         Guard
  │                          │                           │
  │── GET /api/me ──────────►│                           │
  │                          │ set XSRF-TOKEN cookie ──► │
  │◄── Set-Cookie: XSRF ────│                           │
  │                          │                           │
  │ (клиент сохраняет        │                           │
  │  токен в localStorage)   │                           │
  │                          │                           │
  │── POST /api/data ────────│                           │
  │   Cookie: XSRF-TOKEN     │                           │
  │   X-CSRF-Token: (из LS)  │──► csrf.guard ───────────►│
  │                          │   сравнивает cookie==header│
```

---

## Ключевой момент

Клиентская часть (`client/`) **никогда не использует `document.cookie`**. Куки работают полностью «под капотом» через `withCredentials: true` в axios. Единственное, что клиент читает/пишет вручную — это CSRF-токен, но он хранится в `localStorage`, а не в куке (хотя сама кука `XSRF-TOKEN` тоже существует для серверной валидации).
