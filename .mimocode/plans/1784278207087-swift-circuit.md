# Typed Session Lifecycle: PendingSession / AuthenticatedSession

## Проблема

Текущее `session.d.ts` объявляет `accessToken`, `refreshToken`, `idToken`, `userInfo` как **обязательные** поля в `SessionData`:

```typescript
interface SessionData {
  oauth?: { state: string; codeVerifier: string };
  accessToken: string;      // required
  refreshToken: string;     // required
  idToken: string;          // required
  userInfo: { sub: string; ... };  // required
}
```

Это **нечестно**: до логина `session.accessToken` = `undefined` в рантайме, но TypeScript говорит `string`. Отсюда `!` non-null assertions по всему коду (`session.oauth!.codeVerifier`, `session.idToken!`, `session.userInfo!.sub`).

## Критическая ошибка в предложении `PendingSession`

Предложение:
```typescript
type PendingSession = Session & Partial<Pick<SessionData, 'accessToken' | 'refreshToken' | 'idToken' | 'userInfo'>>;
```

**Не работает как задумано.** TypeScript intersection `string & (string | undefined)` = `string` (не `string | undefined`). `Partial` перекрывает поля, но intersection возвращает более узкий тип. `PendingSession.accessToken` всё равно `string`.

## Рекомендация: Make SessionData Optional

### Шаг 1: `session.d.ts` — сделать поля опциональными

```typescript
// src/types/session.d.ts
import 'express-session';

declare module 'express-session' {
  interface SessionData {
    oauth?: { state: string; codeVerifier: string };
    accessToken?: string;
    refreshToken?: string;
    idToken?: string;
    userInfo?: {
      sub: string;
      email?: string;
      preferred_username?: string;
      name?: string;
    };
  }
}
```

Теперь `Session` честно отражает реальность: до логина поля `undefined`, после — заполнены.

### Шаг 2: `src/types/session.ts` — AuthenticatedSession


### Шаг 3: `src/auth/guards/auth.guard.ts` — AuthenticatedRequest

```typescript
// src/auth/guards/auth.guard.ts
import { CanActivate, ExecutionContext, Injectable, UnauthorizedException } from '@nestjs/common';
import { Request } from 'express';
import { AuthenticatedSession } from '../../types/session';

export interface AuthenticatedRequest extends Request {
  session: AuthenticatedSession;
}

@Injectable()
export class AuthGuard implements CanActivate {
  canActivate(context: ExecutionContext): boolean {
    const req = context.switchToHttp().getRequest<Request>();
    const session = req.session;
    if (!session?.accessToken || !session?.refreshToken || !session?.idToken || !session?.userInfo?.sub) {
      throw new UnauthorizedException('Not authenticated');
    }
    return true;
  }
}
```

### Шаг 4: AuthController — типизированные методы

```typescript
// src/auth/controllers/auth.controller.ts
import { AuthenticatedRequest } from '../guards/auth.guard';

@Controller()
export class AuthController {
  constructor(private authService: AuthService) {}

  // До логина — Session с опциональными полями, честно
  @Get('login')
  async login(@Req() req: Request, @Res() res: Response) {
    const authorizationUrl = this.authService.buildAuthorizationUrl(req.session);
    res.redirect(authorizationUrl);
  }

  // Callback — тоже до присвоения токенов
  @Get('callback')
  @UseInterceptors(OAuthCallbackInterceptor)
  async callback(
    @Query(new ValidationPipe({ transform: true })) query: OAuthCallbackDto,
    @Req() req: Request,
    @Res() res: Response,
  ) {
    const redirectUrl = await this.authService.handleOAuthCallback(query.code, query.state, req.session);
    res.redirect(redirectUrl);
  }

  // После AuthGuard — токены гарантированно есть
  @Get('api/me')
  @UseGuards(AuthGuard)
  me(@Req() req: AuthenticatedRequest) {
    return { user: req.session.userInfo }; // sub: string — не undefined
  }

  @Post('logout')
  @UseGuards(AuthGuard)
  async logout(@Req() req: AuthenticatedRequest, @Res() res: Response) {
    const logoutUrl = await this.authService.performLogout(req.session);
    res.clearCookie(config.session.cookieName, { ... });
    res.json({ logoutUrl });
  }
}
```

## Что НЕ меняется

- `SessionService` — методы `setTokens`, `setOAuth`, `setUserInfo` принимают `Session` и работают с optional полями (присваивание `string` в `string | undefined` — ok)
- `AxiosHttpClient` — уже обрабатывает optional через `?.` и `if`
- `BackchannelService` — не использует сессию напрямую
- `GatewayController` — не использует сессию

## Верификация

1. `npx tsc --noEmit` — проверить что типы компилируются
2. Ручная проверка: в `login` методе `req.session.accessToken` должен быть `string | undefined`
3. Ручная проверка: в `me` методе `req.session.userInfo.sub` должен быть `string` (не undefined)
4. Ручная проверка: `session.oauth!.codeVerifier` заменён на безопасную проверку
