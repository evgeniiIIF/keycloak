### ДУБЛИРОВАНИЕ ЛОГИКИ

#### D1 (HIGH) — Дублирование логики обновления access-токена (DRY нарушено)

Одна и та же операция рефреша токена через Keycloak реализована в **трёх местах** с разной обработкой ошибок и побочными эффектами:

| Место | Файл | Строки | Что делает | Обработка ошибок |
|-------|------|--------|------------|------------------|
| **1. AuthService** | `services/auth.service.ts` | 84–122 | POST к Keycloak → обновление сессии → expire Redis | Различает `invalid_grant` (сессия протухла) vs др. ошибки. При `invalid_grant` удаляет `accessToken`/`refreshToken` из сессии, пробрасывает raw ошибку |
| **2. SessionGuard** | `guards/session.guard.ts` | 37–66 | POST к Keycloak → обновление сессии → expire Redis `user_sessions:{sub}` | Ловит **все** ошибки, оборачивает в `UnauthorizedException('Token expired')` — теряет тип ошибки |
| **3. Axios interceptor** | `http/axios.ts` | 38–106 | POST к Keycloak → обновление сессии → expire Redis `user_sessions:{sub}` | Различает `invalid_grant` vs др. ошибки. При `invalid_grant` — `UnauthorizedException('Session expired')`, при др. — пробрасывает исходную ошибку |

**Конкретные расхождения в поведении:**

1. **POST-запрос** — во всех трёх местах формируется идентичный запрос:
   ```
   POST ${config.keycloak.issuer}/protocol/openid-connect/token
   grant_type=refresh_token&client_id=...&client_secret=...&refresh_token=...
   ```
   Но: `auth.service.ts` и `session.guard.ts` используют `querystring.stringify` (deprecated в Node.js), а `axios.ts` — `new URLSearchParams`.

2. **Обновление сессии** — во всех трёх:
   ```
   session.accessToken = tokenSet.access_token;
   session.refreshToken = tokenSet.refresh_token;
   ```
   Идентичные строки, но `auth.service.ts` также обновляет `idToken` и `userInfo`, а `session.guard.ts` и `axios.ts` — нет.

3. **TTL Redis** — `auth.service.ts` делает `expire sess:{id}`, а `session.guard.ts` и `axios.ts` делают `expire user_sessions:{sub}`. **Ни одно место не обновляет оба ключа одновременно.**

4. **Обработка `invalid_grant`** — три разных исключения:
   - `auth.service.ts`: пробрасывает ошибку как есть (raw Keycloak error)
   - `session.guard.ts`: `new UnauthorizedException('Token expired')` (общее сообщение)
   - `axios.ts`: `new UnauthorizedException('Session expired')` (другое сообщение!)

**Почему это опасно:**
- Любое изменение логики рефреша (например, добавление ротации claims, или retry при сетевой ошибке) нужно применять в трёх местах
- Разное поведение при ошибках ведёт к рассинхрону: один компонент считает сессию живой, другой — мёртвой
- Нет единой точки для логирования/метрик обновлений токенов

**Рекомендация:** Вынести рефреш в единый метод в `AuthService` (например, `refreshTokenForSession(session, redisClient)`) и вызывать его из всех трёх мест. Метод должен: (а) делать POST к Keycloak, (б) обновлять все поля сессии (accessToken, refreshToken, idToken), (в) обновлять TTL обоих Redis-ключей (sess + user_sessions), (г) возвращать типизированную ошибку.

### P1-8: D1 — вынести refresh токена в единый метод

**Файл:** `bff/src/services/auth.service.ts` — добавить метод
**Файлы:** `bff/src/guards/session.guard.ts`, `bff/src/http/axios.ts` — заменить дублирование

**Новый метод в AuthService:**
```ts
async refreshTokenForSession(session: any, redisClient: any): Promise<void> {
  const refreshToken = session.refreshToken;
  if (!refreshToken) throw new UnauthorizedException('No refresh token');

  const params = new URLSearchParams({
    grant_type: 'refresh_token',
    client_id: config.keycloak.clientId,
    client_secret: config.keycloak.clientSecret,
    refresh_token: refreshToken,
  });

  const { data: tokenSet } = await axios.post(
    `${config.keycloak.issuer}/protocol/openid-connect/token`,
    params.toString(),
    { headers: { 'Content-Type': 'application/x-www-form-urlencoded' } }
  );

  // Обновить все поля сессии
  session.accessToken = tokenSet.access_token;
  session.refreshToken = tokenSet.refresh_token;
  if (tokenSet.id_token) session.idToken = tokenSet.id_token;

  // Обновить TTL Redis для обоих ключей
  const sub = this.extractSub(tokenSet.access_token);
  if (sub) {
    await redisClient.expire(`user_sessions:${sub}`, config.session.ttl);
  }
  if (session.id) {
    await redisClient.expire(`${config.session.prefix}${session.id}`, config.session.ttl);
  }
}
```

**В SessionGuard:** заменить дублированный блок на `await this.authService.refreshTokenForSession(req.session, this.redisService.client)`
**В axios interceptor:** аналогично, вызывать `authService.refreshTokenForSession(...)` вместо логики интерсептора
