# Убрать эндпоинт /api/auth/refresh + удаление сессии при invalid_grant

## Цель

- Фронтенд **никогда** не вызывает рефреш — эндпоинт `/api/auth/refresh` удаляется
- BFF **сам** делает рефреш при 401 от backend (HttpClient interceptor) — это уже есть
- Если рефRESH токен тоже просрочен (400 invalid_grant) → **удаляем сессию** → фронтенду 401

## Изменения

### 1. `src/controllers/auth.controller.ts` — удалить эндпоинт refresh

Удалить метод:
```typescript
@Post('api/auth/refresh')
async refresh(@Req() req: Request, @Res() res: Response) { ... }
```

### 2. `src/config/routes.ts` — удалить rule для refresh

Удалить строку:
```typescript
{ pattern: '/api/auth/refresh', session: true, csrf: true, skipExpiryCheck: true },
```

### 3. `src/services/http-client.ts` — удаление сессии при invalid_grant

В методе `handle401`, при `invalid_grant`, **перед** выбросом `UnauthorizedException` — уничтожить сессию:

```typescript
if (isInvalidGrant) {
  Logger.error('HttpClient', 'Refresh rejected', {
    reason: err.response?.data?.error_description,
  });
  // Удаляем сессию — refresh token просрочен
  if (session.id) {
    await this.authService.unregisterSession(session.userInfo?.sub || '', session.id).catch(() => {});
  }
  session.destroy(() => {});
  throw new UnauthorizedException('Session expired');
}
```

Для этого нужно инжектить `AuthService` в `HttpClient` (уже есть) и также `RedisService` или использовать `AuthService.unregisterSession`.

Текущий код `HttpClient` уже имеет `authService` в конструкторе — `unregisterSession` доступен через него.

### 4. Остальное — без изменений

- `token-refresh-lock.ts` — остаётся (защита от race condition при параллельных 401)
- `AuthService.refreshTokens()` — остаётся (вызывается из HttpClient)
- `KeycloakClient.refreshTokens()` — остаётся (вызывается из AuthService)
- `refreshToken` в сессии — остаётся (нужен для рефреша и revoke при logout)

## Итоговая логика

```
Фронтенд → BFF: GET /api/service/users
  → HttpClient подставляет Bearer token
  → BFF → Backend: GET /users
  → Backend: access token истёк → 401
  → HttpClient.handle401():
    → AuthService.refreshTokens() — обновляет access + refresh token
    → Повторяет запрос с новым токеном
    → Фронтенд получает нормальный ответ

--- или если refresh тоже мёртв ---

  → Backend: 401
  → HttpClient.handle401():
    → AuthService.refreshTokens() → Keycloak отвечает 400 invalid_grant
    → session.destroy() — удаляем сессию
    → throw UnauthorizedException → 401 фронтенду
    → Фронтенд: редирект на /login
```
