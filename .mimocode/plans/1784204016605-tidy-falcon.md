# Refactor BackchannelController: Stepdown Rule + remove manual error handling

## Problem

BackchannelController нарушает принципы из CLAUDE.md:
1. Ручное управление HTTP-ответами (`res.status(400).send(...)`) вместо использования NestJS exception flow
2. Дублирование маппинга ошибок — `handleLogoutError` делает то же, что уже делает глобальный `HttpExceptionFilter`
3. Валидация `logout_token` в контроллере, а остальная валидация в сервисе — проверки разбросаны по разным слоям

## Solution

Убрать `@Res()` из контроллера, перенести всю валидацию в сервис, позволить глобальному `HttpExceptionFilter` обрабатывать все исключения.

### 1. BackchannelController — сделать thin wrapper

**Было:** контроллер валидирует, ловит ошибки, маппит на статусы вручную.
**Стало:** контроллер только извлекает токен из тела и передаёт в сервис. Всё остальное — ответственность сервиса и фильтра.

```typescript
@Public()
@Controller()
export class BackchannelController {
  constructor(private backchannelService: BackchannelService) {}

  // Извлекаем токен из запроса → передаём в сервис для обработки
  @Post('api/auth/backchannel-logout')
  @Header('Cache-Control', 'no-store')
  async backchannelLogout(@Req() req: Request) {
    await this.backchannelService.handleBackchannelLogout(req.body?.logout_token);
  }
}
```

Удаляем:
- `handleLogoutError` метод
- Импорт `BadRequestException`
- `@Res()` параметр

### 2. BackchannelService — добавить валидацию токена, исправить типы

Добавить `validateLogoutToken` в начало `handleBackchannelLogout`:

```typescript
// Обработка backchannel logout от Keycloak
//   ├─ нет токена → 400
//   ├─ невалидный JWT → 401/400
//   └─ валидный → проверяем replay
//                    ├─ replay → 401
//                    └─ ок → валидируем sub
//                              ├─ нет sub → 400
//                              └─ есть → удаляем сессии
async handleBackchannelLogout(logoutToken: string | undefined): Promise<void> {
  this.validateLogoutToken(logoutToken);     // проверяем наличие токена или кидает ошибку
  const payload = await this.verifyLogoutToken(logoutToken);  // проверяем JWT или кидает ошибку
  await this.checkReplay(payload.jti);       // проверяем Redis или кидает ошибку
  const sub = this.validateSubClaim(payload); // проверяем sub или кидает ошибку
  await this.destroyUserSessions(sub);       // удаляем сессии
}

private validateLogoutToken(logoutToken: string | undefined): asserts logoutToken is string {
  if (!logoutToken) {
    throw new BadRequestException('Missing logout_token');
  }
}
```

Также исправить `verifyLogoutToken` — заменить `throw new Error(...)` на `throw new UnauthorizedException(...)` чтобы глобальный фильтер корректно маппил на 401 (сейчас `Error` превращается в 500).

### 3. Обновить тесты

Тесты контроллера нужно переписать:
- Контроллер больше не принимает `@Res()`, тесты должны проверять что контроллер вызывает сервис с правильным аргументом
- Тесты на ошибки переносятся на сервис (там они и происходят)
- Контроллерные тесты становятся тривиальными: "вызывает сервис с токеном из тела"
